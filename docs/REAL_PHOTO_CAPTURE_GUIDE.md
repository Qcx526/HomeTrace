# 真实物品拍摄指南：先验证同一只 SONY 水杯

Issue #30，2026-10-28。现在只需要拍一小组登记参考和开发场景，不需要准备大量训练照片。先验证已有的白色、黑把手、带 SONY 标志的那只水杯；钥匙、手表、眼镜等以后逐项验证，不承诺同时支持。

当前网页使用 ORB 提供待核对候选。共享 YOLO + DINOv2 仍是隔离实验，历史复用开发数据最多支持了 10 张正例中的 4 张，真实家庭识别尚未通过验收。下列多视角照片用于分析表面覆盖和实例区分；**不是承诺当前网页直接使用六张参考，也不是承诺补拍后一定识别成功。**

## 现在拍：6 张参考 + 8 张开发场景

用手机普通拍照模式，保留原始 JPG/HEIC 等文件。不要截图、加滤镜、美颜、拼图、AI 修图或通过聊天软件压缩。若格式暂不支持，由程序另生成转换副本，保留原文件与转换记录。画面避免个人证件、可读屏幕、二维码和门锁钥匙细节。

每张都重新按快门拍摄，不从一张图裁切或旋转出多张。画面清晰、曝光正常即可，不要求专业设备。原始照片不要画框；我会提供带候选框的本地审查页，你只需确认或指出边界需要调整。

### 1. 登记参考：6 张

全部拍摄**同一只实体 SONY 杯**，完整保留杯身与把手。建议杯子的高度占画面约 40%–70%，对焦杯身标志。视角角度只是拍摄建议，不是已经验证的算法要求。

| 文件名 | 视角 | 背景 |
| --- | --- | --- |
| `ref_01.jpg` | 正面，SONY 标志清楚 | 浅色桌垫或浅色台面 |
| `ref_02.jpg` | 正面，SONY 标志清楚 | 木纹桌面 |
| `ref_03.jpg` | 从正面向左移动约 30°–45° | 浅色桌垫或浅色台面 |
| `ref_04.jpg` | 左斜，尽量与上一张覆盖相近表面 | 木纹桌面 |
| `ref_05.jpg` | 从正面向右移动约 30°–45° | 浅色桌垫或浅色台面 |
| `ref_06.jpg` | 右斜，尽量与上一张覆盖相近表面 | 木纹桌面 |

左右斜视仍尽量保留部分标志，不用追求精确角度。如果杯子该侧没有标志、被把手遮挡或反光，照实记录；不修改图片补全。背面和俯视并未被这份最小方案完整覆盖，不能据此声称任意视角可识别。

### 2. 开发场景：8 张

参考拍完后，把杯子摆入日常环境，拍完整场景，**不要为了方便识别把照片提前裁成只有杯子**。距离只是建议，可按手机与房间实际情况调整。

| 文件名 | 是否包含目标 SONY 杯 | 拍摄内容 |
| --- | --- | --- |
| `dev_pos_01.jpg` | 是 | 约 0.5 米，正面，桌面上正常摆放 |
| `dev_pos_02.jpg` | 是 | 约 1 米，左斜视，换一个实际摆放位置 |
| `dev_pos_03.jpg` | 是 | 约 1 米，右斜视，旁边有普通杂物但杯身大部分可见 |
| `dev_pos_04.jpg` | 是 | 一个困难场景：约 1.5 米较远，或轻微遮挡；记录选择了哪一种 |
| `dev_neg_01.jpg` | 否 | 浅色台面，目标杯移出整个画面 |
| `dev_neg_02.jpg` | 否 | 木纹桌面，目标杯移出整个画面 |
| `dev_neg_03.jpg` | 否 | 只有另一只卡通杯或其他相似杯，没有目标 SONY 杯 |
| `dev_neg_04.jpg` | 否 | 有瓶子、笔筒等日常干扰物，没有目标 SONY 杯 |

负例中的“没有”指整张照片里都没有目标杯，不仅是原先摆放的位置。若目标意外出现在远处或镜面反射中，保留照片并说明，不能继续标为确定负例。目标严重遮挡、自己也不能确定可见区域时，注明 `uncertain`，不强行给出成功标签。

这 8 张用于开发诊断，允许据此发现失败原因。它们一经用于选择参考或改进方法，后续就不能作为独立测试证明提升。所有成功、失败和无法判断的照片都保留，不只交识别容易的图片。

### 3. 干扰杯参考：可选 2 张

现有 `10.jpg` 已有卡通杯身份和 ROI 审核记录，可先复用，不强制补拍。如果方便，再给另一只卡通杯拍正面和斜面各一张，放在 `rivals/`，命名 `rival_01.jpg`、`rival_02.jpg`。确认它们属于哪一只实体即可。缺少新干扰参考会在报告中注明，不用用目标杯照片代替。

用于参考的图片不得同时贡献搜索场景成绩；相同文件的重放会被单独排除。类别同为杯子也不等于同一实例。若两只同款杯肉眼都难以区分，应允许返回 UNKNOWN，不能要求系统凭空确定物理身份。

## 怎么交给我

在本机建立下面的目录，日期用你的实际拍摄日期替换：

```text
F:\qcx\code\HomeTrace\local_data\sony_mug_capture_YYYYMMDD\
  references\     # 6 张目标参考
  development\    # 8 张开发场景
  rivals\         # 可选；没有新增图片可以不建
  notes.txt
```

可以直接保留手机原文件名，在 `notes.txt` 中列出它与上表名称的对应关系，不必为了命名转换或重新保存照片。照片只放本地被 Git 忽略的目录，不上传公共 GitHub。

`notes.txt` 写简单中文即可，例如：

```text
参考图中的目标都是同一只白色 SONY 杯，黑把手。
ref_01.jpg 对应手机文件 IMG_1234.JPG；其他按文件名对应。
拍摄时间：填写实际知道的日期/时间；不知道就写未知。
ref_01/03/05：餐桌浅色垫子；ref_02/04/06：木桌。
dev_pos_01 至 04：目标在画面里；04 有轻微遮挡。
dev_neg_01 至 04：目标已移出整张画面。
dev_neg_03：另一只卡通杯，不是 SONY 杯。
实际光照：填写日光/室内灯等知道的信息。
其他不确定的情况：如实列出文件名和说明。
```

不要照抄示例中不符合实际的内容。不需要补造 `capture_id`、未知采集批次或时间。把路径告诉我后，我会校验文件哈希、尺寸与清晰度，生成参考 ROI 和场景标注审查页；**模型预测不会自动成为人工真值**，最终标注仍需要你确认。

## 之后再拍：独立测试的 14 张

**现在先不要拍这组。** 等开发诊断完成、参考库、模型、预处理、阈值和评分规则明确冻结后，我会通知你开始。新增参考或改变 R3 方法需要另建实验版本与冻结记录，不能覆盖旧 R3 协议，也不能一边看测试答案一边继续调参。

收到冻结通知后，再分两次实际拍摄，每批 3 张正例、4 张负例，总计 6 正例、8 负例。两批更换实际拍摄条件，例如不同位置/背景及日光与室内灯；记录确实知道的时间和场景。不要把同一张照片的裁剪、连拍近重复或改名副本分到两批。

每批暂定覆盖：

- 3 张正例：较近正面、日常距离斜面、较远或轻遮挡各一张，保持可人工定位。具体受限范围在冻结通知中明确，不能拍完再挑容易的样本改变验收范围。
- 4 张负例：空台面、另一只卡通杯、另一只相似杯、普通杂物场景各一张；目标 SONY 杯均不在整个画面内。若没有额外相似杯，提前说明，在拍摄前固定替代方案。

全部原图一次性交付，不先让模型挑选或筛掉失败照片。测试标签不进入检测、参考选择或参数调整。若看完这组结果后还需要改算法，这组就成为已使用的诊断数据，不能再次当作未见测试。

冻结后的受限验收沿用既定标准：6 张正例至少 5 张正确定位（IoU ≥ 0.5）、8 张负例零错误接受、实例 precision ≥ 0.95；零接受时 precision 未定义，不算通过。即使通过，也只能支持这只物品在约定场景下的结果，不代表家庭通用识别、同款实体区分或真实机器人导航已完成。

## 收到第一批照片后会做什么

1. 保存原图与哈希，检查质量和同图重放，给出缺失或无法使用项。
2. 展示登记 ROI 与标注候选，请你确认目标范围和正负例；未知项保留未知。
3. 在隔离实验中对比当前单参考基线与有依据的多参考方案，记录全部定位、误报、拒识和耗时。不会为了返回成功而降低既有门槛。
4. 报告能支持什么、仍失败在哪些场景。只有完成方法冻结后才发出第二批独立测试的拍摄通知。

不需要你为每个物品训练一个网络；本轮优先验证共享预训练模型加参考登记是否足够。合成图片继续只作为明确标记的流程素材，不能替代你的真实物品参考或独立实拍验收。
