# 五张新增实拍：从原位置到近景核对的真实 Agent 流程

2026-11-02，Issue #46 / PR #47 后续验收。程序版本为 `cd75a52d1710608f316df401ea07f2e8d2008d7a`，本轮没有修改生产 Python/JavaScript、数据库结构、检测器、识别阈值或旧报告。新增可选运行配置与本报告、脱敏证据。

## 结论与交付范围

**受限的单水杯、主人参与确认流程本轮完成。** 在真实 HTTP 服务中，真实 LLM 查历史、先检查原地点、读取“未见目标”反馈后换地点、因远景不确定请求近景、读取近景相似建议后请求主人确认。负责人事先明确批准对应图片的身份与位置历史，工程师按该授权通过 HTTP 保存；新服务进程恢复同一事件，真实 LLM 查询到新地点，旧图再次搜索被拒绝且没有重发图片或重复写入。

可以以这一真实能力为范围更新演示材料。**自动实例识别、可靠检测框、独立 6 正/8 负协议和家庭通用识别仍未通过。** 不将本轮称为自动 FOUND、独立识别测试通过或实际机器人运行。正式比赛材料的身份填写、平台格式/容量核验及上传仍是另一个交付环节。

## A. 输入与审计

负责人新提供 5 张 JPEG，并明确顺序对应原空位置、目标新位置全景、同位置近景、相似杯负例、空场景；进一步确认全景和近景仍是同一原有地点 B。公开文档仅用 S1–S5 和 H/B/C，私有名称、原图、标签、哈希、图片授权及完整响应保存在 Git ignored 目录。

全部图片实际解码为 1706×1279，无 EXIF 方向字段，与前两批本机杯子照片没有相同 SHA256。原文件按字节复制，未重画目标、伪造检测框或修改图片内容。每次请求使用同一已批准 ref1 ROI 与完整场景的去 EXIF、最长边 1280 副本；未根据目标坐标裁剪场景。S1/S4 的背景含屏幕与二维码，负责人在本批授权中明确知悉；它们没有进入公共提交。

新验收工作区复制原已验证的 H 主人历史快照（1 条事件），不是回滚含后续历史的现有工作区。原数据库、前轮确认和报告保持不变。目标出现标签只用于操作授权与事后对照，没有送入视觉请求；没有人工真值框，不能计算 IoU。角色顺序和地点来自主人说明，不声称存在可靠拍摄时间、跨批独立性或连续机器人搬动记录。这是新图片的流程诊断，不能代替冻结后的独立实例基准。

## B. 逐图片结果

本地 ORB 两轮均保持原参数，所有图均没有合格 bbox，状态 UNKNOWN。

| 图片 | 主人说明 | 本地匹配/内点 | 覆盖比例 | 视觉顾问实际建议 | Agent 实际动作 |
|---|---|---:|---:|---|---|
| S1 | 原位置 H，目标缺席 | 14/0 | 0 | not_visible → continue_search | 离开已查 H，检查 B |
| S2 | 新位置 B，全景正例 | 15/4 | 0.0053 | uncertain → request_closeup | LLM 调用 request_new_photo |
| S3 | 同位置 B，近景正例 | 18/5 | 0.055 | similar → ask_owner_review | LLM 请求主人核对；授权后保存 |
| S4 | 相似杯，目标缺席 | 13/4 | 0.0153 | not_visible → continue_search | 独立负例会话 UNKNOWN，无候选/记忆写入 |
| S5 | 空场景，目标缺席 | 9/0 | 0 | not_visible → continue_search | 独立负例会话 UNKNOWN，无候选/记忆写入 |

S1–S4 本地拒识为 `insufficient_geometric_inliers`，S5 为 `insufficient_distinct_matches`。没有把零散几何支持解释为实例身份。S2 的远景未被确认，S3 近景改善的是本轮外观核对条件，不能宣称已有可靠自动定位或通用召回率提升。

首轮视觉耗时：S1 13.009 秒、S2 10.160 秒、S3 20.334 秒、S4 16.518 秒、S5 3.673 秒。复跑 S1/S2/S3 分别 10.676/33.645/11.207 秒。S2 复跑产生 4009 个输出 Token，接近 4096 上限，但实际 finish 完整、通过内容校验。模型耗时与输出仍有波动；不是稳定性能基准。

## C. 首轮失败、原因和唯一运行参数调整

首轮 `max_total_tokens=24000`。LLM 已真实查 H、查 B、请求近景，并对 S3 完成本地观察；此时下一次文本决策被 `TOKEN_INPUT_BOUND` 拦截，主流程 **BUDGET_EXCEEDED，零新主人记忆**。没有把它报成成功，也没有自动重试。

冻结失败状态只读复算：已实际使用 14011 Token，下一请求保守输入上界 11145，总计超过 24000；剩余为 -1156，程序正确停止。这是上下文与运行预算不匹配，不是本次 API 已超支或检测阈值不足。首轮尚未发送 S3，于是同一有效授权账本中另跑 S3 控制；它得到相似建议，停在 AWAITING_REVIEW，没有保存。S4/S5 为独立负例会话，不能说它们都发生在同一条搜索链里。

第二轮只将私有运行配置的文本总预算设为 **32000**（现有配置验证器允许的上限）。原 10 次模型调用、12 次工具调用、5 地点、45 秒超时、零重试不变；单次视觉最多 3 次、视觉总预算 24000、输出上限 4096 均不变。未改预算算法、源码、模型、视觉判据或生产默认 `config.yaml`。

此失败状态在 32000 下有 6844 Token 的请求余量。随后真实复跑完成，不是只做数学估算。新增 [config.photo-demo.yaml](../config.photo-demo.yaml) 与实际执行配置解析后的内容完全相同，便于材料和演示复现。更大预算可能增加费用，不能保证所有场景都会成功；云端失败仍应明确停止。

## D. 第二轮真实执行与来源

| 阶段 | 实际结果 |
|---|---|
| 查历史与搜索 | 配置中 B 排在 H 前面，LLM 仍根据 H 历史先检查 H；原位置有实际照片，不再是缺图 |
| 第一次观察 | S1 not_visible，LLM 选择检查 B |
| 第二次观察 | S2 uncertain，LLM 选择请求近景；操作员提交主人已提供的同地点 S3 |
| 第三次观察 | S3 similar，LLM 选择 request_owner_review；没有凭意见生成检测框 |
| 保存 | 负责人对本轮 S2/S3 与地点的明确授权在先，工程师通过 HTTP accept_candidate 执行；USER_CONFIRMED，恰好新增 1 条 owner_reported，visual_confirmed=false |
| 实际重启 | 新 PID、同一工作区，读取到完全相同的已确认 run |
| 历史查询 | 真实 LLM 返回新照片地点历史，明确不保证此刻仍在那里 |
| 旧图重放 | 再搜索原 S1/S2，均 replayed_image_content，UNKNOWN，零视觉外发、零新主人事件 |

补图只更新当前 run 快照；全局地点照片仍为原 S1/S2，因此重放检查的是它们，未虚称对 S3 又做了一次全局重放。

确认动作是**依据明确授权的 HTTP 操作**，本轮没有负责人亲自点击网页或新的浏览器点击验收。Windows Computer Use 无法可靠确认当前浏览器 URL，工具停止后未继续 UI 操作。网页回归 28 项通过；前轮实际浏览器保存证据仍在原报告中，不能算作本轮新截图。

两批授权严格分开：第一批最多 5 次，S1–S5 各一次；负责人另行批准第二批最多 3 次，S1–S3 各一次。共 **8 次真实视觉调用**，每个批次每张一次、零自动重试。每批以一个 ConsentLedger 在所有主流程/控制会话间持有，发送前核验哈希、目的地与次数并持久预留，未复制账本重置额度。本轮授权已用完。

## F. 材料可以写什么

可以展示“历史记忆 → 真实 LLM 工具决策 → 原处未见 → 换地点 → 请求近景 → 主人确认 → 持久记忆”，明确照片由主人提供、导航模拟、最终身份由主人核对。LLM 不是只生成解说词，实际调用了搜索、视觉请求、补拍与核对工具。

不能写自动可靠识别所有家庭物品、自动机器人扫描、可靠检测框、自动 FOUND、长期习惯学习已验证或搜索效率已提高。本轮仍仅一件水杯，且 S2 全景需近景辅助；三个负样本没有错误候选并不证明通用误报率为零。

现有五张照片已足够完成本轮受限流程验收，不再以继续补拍为材料准备的前置条件。后续若追求自动实例定位，另按独立标注与冻结协议验证。现在可以按上述范围更新 Word、PPT、视频和测试报告；团队身份按负责人要求留空待填写，旧包不能直接改名当作新提交包。
