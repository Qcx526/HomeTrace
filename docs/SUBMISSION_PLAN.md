## 3. 交付故事

观众看得懂的主线：一个目标物品已登记且历史位于 A；用户将物品移到 B（当前真值不能提前提供给搜索决策模块）；任务先去 A，读取当前真实图像并确认没有可靠找到；根据记忆与当前观察调整计划；在 B 的实际图片中识别候选并验证；生成包含地点、证据图像、实际搜索轨迹的报告。另有负例明确输出 UNKNOWN。

主张是“记忆驱动的自主寻物决策与可追溯结果”，不是“原创视觉基础算法”。说明开源组件及项目内的系统适配工作。不能把模拟导航包装成机器人真机运行，不能拿人工 fixture 标注当作视觉模型预测。

## 4. Codex 一键打包工具要求

实施脚本：`tools/build_submission.py`（可按实际工程结构调整，但需单一入口）。

- 接受一个**本地配置文件**或交互输入的团队名称、作品名称、队长姓名和队长手机号；不要将真实个人信息提交到 GitHub。
- 接受官方已填写 docx、PPT、MP4、运行报告路径；不得通过占位文本伪造官方文件或演示结果。
- 自动导出限定的核心源码快照，避免打进 `.git/`、`.venv/`、`artifacts/`、`__pycache__/`、`*.sqlite3`、临时缓存、密钥、`.env`、私密数据图像、旧版提交 ZIP。
- 输出到本地 `dist_submission/`（gitignore）；在最终 ZIP 中按约定排序，生成目录清单、代码 Commit/来源说明和归档校验摘要。**不得自动推送 ZIP 到公开仓库**。
- 对必要材料缺失、模板仍空白、zip 内文件为空、重名、压缩包命名不合法、视频/Word 无法读取、未确认的隐私信息等进行预检，失败时非零退出；无法自动判断 Word 是否“内容已填好”时明确提示人工检查，不可声称通过。
- ZIP 使用标准 UTF-8 文件名，解压后不存在绝对路径、`../` 路径、不安全软链接。打包后重新打开 ZIP 检查完整性、条目和文件校验。
- 可使用标准库 `zipfile` + `pathlib` 完成打包；尽量不要引入沉重依赖。
- 一键打包运行示例写到 README；提供只含假姓名/假电话的脚本测试用例。正式电话仅在本地传入。
- 不硬编码未经核实的官方上传大小限制；可显示实际 ZIP 大小供用户对照提交平台要求。
- 可选生成 `manifest.sha256` 在 ZIP 外进行完整性核对；不得将其误称为官方要求。
