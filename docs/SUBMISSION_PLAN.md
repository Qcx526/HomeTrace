## 交付与外部核验

内部目标为 Word、PPT、真实软件运行 MP4、核心源码、运行及测试报告、开源与原创性说明和材料清单齐全。Word 使用 `HomeTrace_作品设计与技术说明书.docx`，`document_source=team_authored`；团队身份字段可在公开版本保留待填，最终本地填写。

材料齐全可生成并校验 `candidate` ZIP。模板未知不是开发或候选打包的阻塞项。候选包不等于 `officially_verified`，也不等于 `uploaded`；打包器不得自动给出这两个状态。

提交前由负责人实际打开**本届赛事“提交作品”页面**，核查允许格式、文件命名、大小限制、必选附件或下载模板、截止时间；若明确要求指定格式再替换。现有团队计划为 10 月 27 日形成候选包、10 月 28 日 12:00 前上传，该时间及此前命名 `实物组-团队名-作品名称-队长姓名-队长手机号.zip` 均需对照当届平台复核。不得把历史资料或其他年份规则当作已验证的本届规则，不硬编码未确认的官方大小限制或提交次数。

## 统一叙述与证据

作品创新是“历史时空记忆 → 主动选择观察点 → 当前图像验证 → 可追溯结果”，包括历史/当前证据分离、未确认状态和旧图重放保护。视觉使用成熟开源 ORB、Hamming 和 RANSAC 单应性检验，不宣传原创基础识别算法。

公开 OpenCV 实拍图是稳定回归路径，A/B/C 和时间为演示编排；导航始终为模拟，没有真机运行。三个公开场景分别展示 FOUND/B、未确认负例和旧图重放拒绝；两种策略在这些样例中步数打平，不能宣称已证明效率提升。

团队实拍照片单独本地评估。检测失败仍是 SUSPECTED/UNKNOWN，不把人工标签当检测输出，不放宽阈值追求成功，不补写不存在的历史搬移。私密钥匙、二维码、屏幕和原图不公开；材料只能使用已核验的数字汇总。家庭适用性结果见 [照片实测](TEAM_PHOTO_EVALUATION.md)。

## 单命令工具验收

入口 `tools/build_submission.py`，实现与命令见 [打包工具](SUBMISSION_TOOL.md)。

- 本地配置选择自编说明书、PPTX、MP4、报告、原创性说明和代码目录；团队名、作品名、队长和电话只在本地读取。未知身份不得用假姓名手机号伪装真实队伍。
- 缺少必备材料、空文件、不可读格式、不安全路径或敏感源码应非零退出。缺失平台核验、身份待填保留候选状态，不阻断内容齐全的 candidate。
- 限定源码范围，排除 `.git`、虚拟环境、缓存、数据库、私密照片、密钥、临时日志和旧 ZIP。公开样例按来源白名单保留，不直接压缩整个工作区。
- 记录 Git 来源与实际内容摘要，明确脏工作区；候选包不得冒称已审查提交。发布时由负责人选择 PM 审查后的代码。
- ZIP 中相对路径唯一、无链接逃逸、无绝对路径及 `../`。生成后重新打开检查 CRC、条目与逐文件 SHA256；输出实际大小和验收报告。
- TEST_ONLY 自动化夹具与实际成果包分开命名，不冒充比赛提交。
- 工具不上传、不写入公共仓库、不自动宣称官方验证或上传成功。
