# HomeTrace 提交材料清单

当前以 Issue #12 为准：官方主表在 Git ignored 本地填写，七页技术说明书仅作补充。下表现有媒体是 P3 历史成果；Agent/神经网络内容只在相应 PR 审核合并后依据实际结果更新。本清单不表示已完成赛事上传。

| 材料 | 文件或入口 | 提交前检查 |
| --- | --- | --- |
| 官方主表 | 本地原件与单独填写稿 | 保持原表结构、300 字以内、真实身份一致；当前身份缺失 BLOCKED |
| 作品设计与技术说明书 | `HomeTrace_作品设计与技术说明书.docx` | 正文与实测一致；团队字段在本地补全；所有页面可读 |
| 技术展示 PPT | `HomeTrace_技术展示.pptx` | 10 页，截图来源明确，文字与 DOCX/视频一致 |
| 演示视频 | `HomeTrace_演示视频.mp4` | 72.28 秒，中文字幕，无音轨，公开三场景；完整解码已通过 |
| 核心源码 | 打包工具限定导出的仓库文件 | 排除私图、数据库、密钥、环境、缓存；记录 commit |
| 运行说明与测试报告 | `RUN_TEST_REPORT.md` | 区分 P2 历史基线与 P3 本轮结果；保留失败原因 |
| 开源技术与原创性 | `OPEN_SOURCE_AND_ORIGINALITY.md` | 保留公开图片来源与许可；基础算法不冒称原创 |
| 团队配置 | 本地私有配置 | 名称、队长、电话和最终命名由团队核对，不提交 GitHub |
| 提交 ZIP | 本地 `dist_submission/` | 所有门槛通过后生成；重新打开、SHA256、人工解压查看 |

最终门槛：身份字段真实完整，文件均可打开，视频与源代码版本一致，私密数据清除，内容经 PM 审查，赛事平台的实际命名与上传要求经负责人核对。候选 candidate 包可以保留明确未完成的人工审查状态，不能称为正式 ready。没有真实完整正式 ZIP 与解压核验之前，不宣称“可直接提交”。

材料生成脚本：`tools/create_submission_materials.py`（DOCX）与 `tools/create_submission_materials.mjs`（PPTX）。这两个工具只生成叙述材料，不生成官方凭据、识别结果或比赛提交回执。最终运行证据由独立验证命令产生。
