# 真实水杯照片闭环：Issue #46

2026-11-02，基于未合并 PR #45 的 `c594c6e6d2e49deb8520c12fe93846dedad785e7`，在 `feature/46-real-cup-workflow` 增量开发。负责人要求先完成真实物品验收再继续打包，因此本轮没有制作或更新提交材料、ZIP，没有合并任何 PR。

## 结论

已实际完成一件真实水杯的 **主人参与确认** 流程：读取原主人历史 → 先检查历史地点但明确缺图 → 实拍负例本地观察 → 另一地点实拍正例 → 真实视觉外观建议 → 真实 LLM 选择请主人核对 → 负责人明确确认身份与照片位置历史 → 在网页点击保存 → 新服务进程查询到同一条新记忆。再次使用旧图搜索时，两张照片均因重放被拒绝，没有再次外发或重复写主人记忆。

另做一个真实负例控制：使用本批尚未发送的负例照片，直接运行生产 Agent service，真实视觉返回 `not_visible`，真实决策 LLM 结束为 UNKNOWN。它不是正例会话里的第二次视觉调用，也不是浏览器操作验收。

**自动实例识别、可靠检测框和家庭通用识别仍未通过。** 本地 ORB 在正负例上都没有合格框。正例是模型外观建议加真实主人审核，不能记成自动 FOUND；独立测试集仍为 0。图片回放不证明实际移动先后或当前实物地点。

## 输入、选择与授权

- 使用此前批准的单参考及固定 ROI，不训练新网络、不挑换参考、不降低匹配阈值。
- 使用两张既有真实照片：P 为先前可辨认的目标出现图；N 为包含玻璃容器的目标缺席图。这是按既有诊断选择的开发样本，不是盲测，不能据此估算泛化准确率。
- H 为真实主人原位置陈述。H 与 N 的拍摄地点不同，H 没有当前照片；系统报告 `no_observation`，没有移用 N 冒充 H 的空场景。
- 原图哈希逐项核验，SQLite backup 复制原历史到新验收工作区；原照片、源工作区、旧报告均不覆盖。没有伪造拍摄时间、移动过程、真值框或当前实物位置。
- 两次明确图像授权，每批最多两张、每张一次、零重试，接收方为已配置第三方网关。第一批仅发送 P，失败消耗名额；第二批发送 P 和 N 各一次，总计真实图像调用 **3 次**。第一批未用名额不挪用。
- 第二批的 N 是正例会话结束后做的独立负例控制：检查前一执行已正常结束、原授权哈希、原账本、未发送的 N 哈希和剩余总数，锁定同一账本，先追加唯一预留再批准发送；不重置计数、不重传 P、不从失败中自动恢复。私有记录保留两个运行与同一授权的绑定。
- 外发仅去 EXIF、最长边 1280 的固定参考 ROI 与完整场景副本，场景背景保留。无标签、地点名或真值坐标进入视觉请求。私人照片、物品与地点绑定、授权原文、数据库及完整响应只保存在 ignored 目录。

## 最小修复及理由

1. `visual_advisor_client.py` 的在线请求上限单独设为 4096，保留 45 秒、零重试、不跟随重定向。冻结实验的 `visual_advisor.PARAMETERS['max_tokens']=2048` 及旧报告不改。
2. 截断明确返回 `OUTPUT_TRUNCATED`，即使残缺返回看似合法 JSON 也拒绝使用。可选记录合法的 reasoning 数值子项和请求限制，绝不保存模型内部推理正文。服务成功/失败证据均保留这些安全元数据，每次视觉调用预留 8192 Token、总预算 24000 Token 均不放宽。
3. 网页 `?run=<32位小写hex>` 用 GET 加载指定既有会话，便于真实审核和重启恢复。加载本身不发起运行、图片授权或主人确认；非法/重复/失效编号不回退其他会话。正常人工按钮保持原行为。
4. 网页明确显示输出截断，失败卡片与工具轨迹只展示元数据，不把截断正文呈现为视觉结论。

本次只观测到“旧设置一次截断、新设置一次成功”。成功回复实际输出 840，小于旧上限 2048；因此 **不能把结果差异全部归因于扩大上限，也不能宣称已证明稳定修复**。第一次没有 reasoning 分项，不能断言它的 2048 全是推理 Token。新上限可能增加耗时/费用，仍须继续观察真实失败。官方文档说明 `finish_reason=length` 的截断含义，可参考 [Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)；本项目网关并非官方直连，官方参数支持不能代替本机网关实测。本轮未发送新的供应商专属 thinking 参数。

没有改 ImageMatcher、SearchCore、SQLite schema、注册阈值、模型、识别 JSON 判据、Agent 工具选择策略或图片权限规则。LLM 本次跳过了对 N 的视觉调用，只做了本地观察；报告没有把它描述成先看负例云端意见再重规划。独立负例控制补足的是一次真实模型拒识证据，不是完整误报统计。

## 还缺什么、何时再打包

- **一个真实水杯的主人辅助回放闭环有证据了**；它不等于自动检测定位完成。
- 历史地点 H 缺当前观察。要验证实际“原处没有 → 新处发现”，最小补拍是 H 空场景一张、新放置地点完整场景一张、同地点近景一张，并由主人说明这次真实操作顺序；不要拿不同桌面的旧图拼成移动事实。
- 需要至少一张相似杯/容器和一张空场景的新增负例，检查实际错误拒识/错误候选。以上是小型流程验收输入，不冒充冻结协议要求的独立 6 正/8 负。
- 自动实例定位的既定独立验收仍需冻结方法后两批新的 6 正/8 负及人工定位标注；当前没有检测框，不能计算 IoU 或宣称达标。
- 本轮仅一件物品。多物品目录的软件能力不等于钥匙、眼镜、手机等已经验证。LLM 意见、云端可用性、小目标/遮挡与相似外观仍有限制。
- 当前仅按主人记录排序，没有证据证明学会了长期放置习惯或提高了通用搜索效率；导航始终模拟。
