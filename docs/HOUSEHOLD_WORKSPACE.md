# 家庭记忆工作区：Issue #24

日期：2026-10-27。任务合同：[Issue #24](https://github.com/Qcx526/HomeTrace/issues/24)。本分支 `feature/24-household-workspace` 基于 PR #23 的 `1aa8526`，是 stacked PR；目标分支为 `feature/22-shared-visual-memory`。不合并任何 PR，不改变生产视觉、SearchCore、Agent 或生产 SQLite schema。

## 输入和实际行为

本轮把已有主人陈述 CLI 做成持久家庭工作区：名称/别名登记 → 明确地点 → 同名选择 → 确认保存 → 重新查询历史。每件物品有稳定 ID；名称登记不是外观登记。页面输入已登记的名称、别名或编号，不解析自由自然语言，也不调用 LLM。

“这里”必须由用户选择玄关托盘、书房桌面或客厅茶几。没有自动定位主人、摄像头扫描或机器人移动。回复“好的，我已记录你说的位置；尚未通过当前图像确认”只对应实际保存的 `owner_reported` 事件。所有记录 `visual_confirmed=false`，不会生成生产 FOUND。

查询时按每个地点的最新陈述排序，同时显示该地点陈述次数；没有学得概率、长期习惯推断或已证明的搜索效率提升。历史是线索，不能证明物品现在仍在那里。

## 启动与演示

仓库根目录，Python 3.11+：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e ".[dev,vision]"
.venv/Scripts/python.exe -m hometrace demo --port 8765 --output-dir artifacts/p2-demo --household-dir artifacts/household
```

打开 `http://127.0.0.1:8765/household.html`。本工作区本身只需 Python 标准库；`vision` 供原照片 Demo 使用，`--agent` 与其可选依赖保持原行为。本轮没有验证真实 LLM API。

页面验收顺序（2026-10-27 已通过真实浏览器操作执行；禁用 localStorage 的分支未实测）：

1. 登记 `blue-keys`（蓝色钥匙）与 `red-keys`（红色钥匙），都添加别名“我的钥匙”。这些是软件演示名称，不是真实照片或真实家居位置。
2. 选择“记住位置”，输入“我的钥匙”，地点选“玄关托盘”；页面应要求选择哪件物品。选择蓝色钥匙后进入待确认状态，尚未保存位置。
3. 刷新页面，再停止服务并用同一个 `--household-dir` 重启；同浏览器、同 URL 应恢复待确认状态。浏览器只保存会话编号，目录和会话内容都在本地 SQLite。若禁止 localStorage，则提示无法自动恢复。
4. 确认后查找历史，应有且仅有一条主人陈述；另开记住操作并取消，不得增加历史。多页面持有旧版本时应提示冲突，刷新当前状态后再操作。
5. 输入未登记“我的水杯”，先登记该名称，再用“重新查询”继续原会话；不自动选择别的物品。
6. 新记录书房桌面位置，查询应优先列出书房桌面，保留玄关历史。不能把这个顺序叫作真实搜索已经执行。

初次验收因浏览器工具禁用而未执行，原记录保留。负责人重启应用后，已使用内置浏览器完成上述主流程和窄屏布局检查，保存真实截图、14 份页面快照、服务请求日志及最终只读数据库计数，见[浏览器补验收](evidence/issue-24/browser-20261027/README.md)。旧页面取消操作实际收到 409 并恢复已完成状态，未覆盖已确认位置。此补验收仍不等于跨浏览器、手机实机或视觉识别验收。

## 核心结构与故障处理

| 文件 | 职责 |
| --- | --- |
| `src/hometrace/household_memory.py` | 从 `tools/household_memory.py` 原样迁入包内的既有记忆模块；保留 schema 与旧 CLI，增加外层事务兼容及时间来源说明 |
| `src/hometrace/household_service.py` | 登记、解析、确认、取消、重试、历史查询与持久会话版本控制 |
| `src/hometrace/demo_server.py` | 本机 API 与静态页面；沿用 Host/Origin 检查，严格字段白名单 |
| `src/hometrace/web/household.*` | 物品目录、确认控件、实际交互消息和历史视图；用户文本用 textContent 渲染 |
| `tools/household_memory.py` | 兼容原命令与导入的薄封装；安装包后使用 |
| `tools/validate_household_workspace.py` | 启停两个真实 CLI 进程，执行跨进程 HTTP 验收；只用虚构软件陈述 |

`owner-memory.sqlite3` 保存名称及不可覆盖的位置事件，`sessions.sqlite3` 保存会话；两者在 ignored 工作区中。会话更新使用 owner 连接 ATTACH 会话库、检查 DELETE journal、BEGIN IMMEDIATE，把位置事件与会话状态一起提交。遇到 UPDATE 失败会同时回滚；不允许出现“位置已保存但页面报告取消”的半保存状态。外部改成 WAL 时拒绝写入，不默默假设跨库事务仍原子。

事件 ID 从会话 ID 派生。最新版本重复确认不增加事件；旧版本返回 409。同一个版本的确认/取消竞争经事务与版本号串行化。存储故障不会回复保存成功。此处故障注入验证不等于实机断电/文件系统损坏验证。

时间来源分别记录：`owner_supplied_timestamp` 为主人填写，`session_creation_time` 为服务收到开始请求的本机时间。后者不是拍摄时间，也不是主人亲自报出的时间；`recorded_at` 是入库本机时间。旧 CLI 记录仍按原合同解释。

## 实际验收证据

完整命令、计数和哈希见 [本轮证据目录](evidence/issue-24/README.md)。本轮全量回归 **630 项通过、0 失败、0 跳过**，含基线 576 项和新增 54 项；不是不同分支结果相加。一条既有 LangGraph 弃用预告保留。

真实 CLI/HTTP 验证执行 2 个独立服务进程、20 次请求：同名解析、未确认无写入、停止后恢复待确认、确认保存、409 冲突、重复确认、取消、未知对象登记后重试、不同物品隔离和历史排序通过。最终蓝色钥匙 2 条位置陈述，取消的水杯 0 条，候选顺序书房桌面 → 玄关托盘。后续浏览器独立使用新工作区执行主流程，最终数据库同为蓝色钥匙 2 条、红色钥匙及水杯各 0 条；全部为 owner_reported / visual_confirmed=false。补验收只新增文档和证据，未改源码，未把页面检查次数加入 630 项 pytest 计数。

测试还覆盖事件 INSERT 后会话 UPDATE 故障回滚、两个服务并发确认、ID 不可重绑、外部 WAL 拒绝、字段/类型/长度/路径/Origin/Host 拒绝。测试 fixture 不是家庭识别证据；本轮没有新的照片推理、训练、API 模型调用或机器人运行。

## 当前问题与下一步

本增量完成主人陈述记忆、持久确认接口和浏览器主流程验收，不是完整家庭寻物产品。真实照片参考登记、共享编码器与工作区连接、自然语言多轮入口及当前场景扫描尚未实现。已有照片 Agent 与本工作区独立运行，不声称两者已贯通。页面刷新后上方新请求表单恢复默认值，下方已保存交互恢复正确；首次图标请求出现不影响主流程的 favicon 404。未执行跨浏览器、禁用 localStorage 和手机实机验证。

家庭实例视觉仍 **BLOCKED**。PR #23 的复用开发图检索仅支持 3/10（640）或 4/10（960）正例，不能当作独立测试或家庭识别通过；此次没有改变这些历史结论。下一步最小改动是私有照片参考登记与人工确认入口，并在隔离实验模式展示共享模型候选及 UNKNOWN，之后才考虑接入可信搜索流程。不能让人工位置陈述或模型相似度单独决定 FOUND。
