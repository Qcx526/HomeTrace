# 视觉反馈后的决策收敛：Issue #38

基于 PR #37 的 `66eae126aa775e76d58e5de06116f184d3ae7770`，在 `feature/38-feedback-decisions` 增量开发，目标分支为 `feature/36-real-cup-agent`。不合并上游，不重写 Issue #36 的实拍报告。

## 主人审核与已知问题

负责人明确确认了此前三张待核对场景照片均是登记的同一只实体水杯。该人工身份审核单独保存在本地 `artifacts/issue-38/owner-review-01.private.json`，绑定原图哈希、运行编号和观察序号。它只说明身份，不确认拍摄时间、实际地点或数值真值框，不是模型自动识别结果，也不是新的独立测试。

没有执行原会话中的 `accept_candidate`：该操作还会保存演示映射地点为主人记忆，而本次批准并不包含实际地点。原会话、原始模型意见、照片和已冻结报告保持不变。本轮没有新的图片外发权限；Issue #36 十次额度已经用完，不重复传图。

先前真实运行显示：`not_visible` 意见后，Agent 仍可能要求新视角；`similar/ask_owner_review` 且无本地框时，也可能继续索要近景。本轮优先减少这些不必要的补拍，不修改视觉阈值或训练新模型。

## 最小变更

Agent 改动只在 `VisualPhotoAgentService` 增补公开提示和结构化 `decision_support`：

- 仅描述最新观察的顾问状态、外观判断、建议、质量标记和本地框是否存在。
- 列出尚未检查且已有上传图片的地点；这不扩大用户允许的搜索范围，不保证图片尚未使用或目标存在。
- 明示当前证据是否支持主人核对。旧视角意见不能当作新图结论。
- 提示模型：未见目标或外观不同通常换地点或停止；可以核对的相似外观优先主人核对；具体细节不足才定向请求新视角。

实际动作仍由 LLM 返回工具调用。工具白名单、调用参数、图像授权、预算、Core 校验和人工确认事务维持原规则；没有添加根据 appearance 自动跳转的规则引擎，也没有预选答案字段。模型仍可能不遵循建议，不能由文本提示推断稳定性保证。

## 验证方法

新增确定性回归使用明确的模型、顾问和图像 fixture。另做有界真实文本决策对照：六种不含图片和私人描述的软件反馈场景，每种旧版/新版各一次，共最多十二次 API，无重试、不执行返回的业务工具。预期动作只在响应后用于评分，不进入模型输入。

该对照比较的是“提示 + 工具说明 + 最新反馈摘要”的整体增量，不是仅改一个变量的统计实验。它只能检验这些公开软件场景中的工具选择，不能证明重新识别了水杯、获得了新检测框，或完整家庭链路已经通过。

## 实际结果

2026-10-30，固定六个软件场景各运行旧/新配置一次，共十二次真实文本 API 调用，无重试。实际返回均符合工具协议，无调用错误；旧版 **4/6**、新版 **6/6** 符合事前定义的动作预期。

| 软件反馈场景 | 旧版实际选择 | 新版实际选择 |
|---|---|---|
| 未见目标，仅允许当前地点 | 要求补图 | 结束 UNKNOWN |
| 明确外观不同，允许另一处已有图地点 | 检查另一地点 | 检查另一地点 |
| similar、建议主人核对，无框、视角不同 | 要求补图 | 请求主人核对 |
| uncertain，小目标且遮挡 | 要求补图 | 要求补图 |
| similar，但明确建议近景、小目标 | 要求补图 | 要求补图 |
| 未见目标、背景杂乱，有另一处图像 | 检查另一地点 | 检查另一地点 |

旧版实际用量 10337 Token，新版 11828 Token。两个版本均通过同一已配置第三方接口，请求模型 `deepseek-v4.1-flash-1017`；此为接口记录的模型标识，未独立验证网关背后的模型身份。网络超时 45 秒、重试 0、最大输出 1024 Token。新版增加提示上下文，Token 开销也增加，不宣称更省调用费用。逐调用输出、耗时、工具参数、源码/提示哈希与依赖版本见 [evidence/issue-38](evidence/issue-38/)。

该小样本中，新版修正了两次不必要补拍。每种组合只运行一次，且输入为明确的软件反馈，不能据此保证线上稳定性、给出统计显著性或宣称实拍效果提升。本轮零图像请求、零实际业务工具执行；真实 API 输出仅记录与校验。独立离线 service 回归另验证了工具确实能执行停止、换地点和无框主人核对，也验证模型仍可在负例反馈后选择有明确理由的补拍，未把提示改成硬编码动作。

## 全量回归发现的 HTTP 缺陷

首次全量回归为 **987 passed、1 failed**（148.81 秒）。失败项是旧有的 `test_http_rejects_external_hosts_origins_and_form_posts[headers2-415]`：服务器已经发送 415，Windows 客户端却收到 WinError 10053。基线已有提前拒绝 POST 正文的路径，与本轮 LLM 改动无关。

进一步复现：原请求连续 100 轮、三种拒绝条件共 300 次，298 次收到预期状态、2 次连接重置；将相同非法 Content-Type 请求的头与正文一次发送，100/100 返回 415；延迟 50 毫秒再发送正文，则 0/20 收到响应。问题是 HTTP/1.0 服务未消费正文就关闭连接，与稍后到达的正文发生竞态。定向 pytest 单次通过不能证明这个问题不存在。

已在 [Issue #38 补充范围](https://github.com/Qcx526/HomeTrace/issues/38#issuecomment-6518152150)：修复提前拒绝时的正文处理，加入延迟正文回归；保持拒绝规则不变，不修改原测试、增加自动重试或吞掉连接异常来制造通过。首轮失败和原始诊断记录保留在本地忽略目录，公开验证摘要一并记录失败。

2026-10-31 完成的修复在提前返回 403/404/415 前，只丢弃单一合法 Content-Length、无 Transfer-Encoding 且至多 64 KiB 的 POST 正文，最多等待一秒总时间，不解析、不调用业务服务，随后恢复连接超时并返回原错误。超限、歧义或超过期限才到达的正文仍可能导致连接错误，不承诺任意恶意请求均能收到响应。

修复后同样的传输对照为一次发送 **100/100**、延迟正文 **20/20** 收到 415。新增测试覆盖延迟正文的四条拒绝路径、缺失正文超时、模糊/非法/过大长度不读取、慢速到达不能延长期限及业务零调用；与原 Demo 测试一起 **34 passed / 19.56 秒**。这是本地真实 TCP 传输验证，不是机器人动作或视觉识别实验。

修复后的联合全量实际结果为 **1003 passed / 151.73 秒**，一项原有 LangChain 弃用提示；前端 **21 passed**。新增 24 项决策/探针测试和 15 项 HTTP 测试均为软件回归，不能计入真实照片数量。这里使用本分支完整运行结果，没有把不同分支测试数相加。
