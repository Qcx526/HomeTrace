## Issue #4 的打包输入契约

以下是对既有合同的准备整理，不是当前已存在的脚本参数：

- 本地提供已填写的官方 DOCX、技术展示 PPTX、真实运行 MP4、运行与测试报告、开源与原创性说明，以及团队名称、作品名称、队长姓名/手机号。
- 从审核过的代码提交导出限定源码、测试、运行说明和允许公开的样例。不要把整个开发目录直接压缩；排除 `.git`、虚拟环境、SQLite、缓存、临时运行文件、密钥、私密图像和旧 ZIP。
- 正式文件名称遵从官方附件指示；目录布局可沿用既有合同的建议结构。不要将建议结构或内部 PPT/视频门槛称为赛事官方格式。
- 打包前检测缺失、空文件、不可读取文档/视频、非法名称及未确认的隐私信息；文件可读取不等于正文已填完，内容仍需人工核对。
- 在本地 `dist_submission/` 生成 ZIP，记录代码提交和文件清单，重新打开并检查完整性、相对路径及各文件摘要，然后人工解压查看。正式 ZIP 和个人信息不推送到公共 GitHub。
- 只显示实际文件大小供负责人对照平台要求，不擅自设置未经核实的官方容量限制。
